# Horosa 星阙 v3.11.3

本版是 v3.11.2 之后的启动体验与更新链版本:**安装或更新后第一次打开不再多等十几秒**,应用内增量更新完成后的第一次启动同样快;温启恢复到上次停留的页签;若干本地服务与安装链的稳健性修正。排盘结果不变。

---

## 安装 / 更新后第一次打开

- **安装后第一次打开盘不再等十几秒**:系统对新安装的原生组件要逐个做一次首次加载检查(约 250 个、串行),此前这一步发生在你第一次点开盘的时候。现在安装完成时就在后台把检查做完(最多等 30 秒,没做完的留在后台继续),打开软件即可正常出盘。
- **应用内更新后的第一次启动同样快**:增量更新时未改变的组件保持原有的文件身份,系统的首次加载检查状态跟着保留;只有本次真正替换的组件需要检查,并且在更新完成、服务启动之前就带进度做完(「正在完成新版本的首次加载检查 n/N」),不再表现为「更新完成后卡住十几秒」。完整更新、首次自动安装也一样。
- **主排盘不再等卜类引擎装完**:本地排盘服务分两级就绪 —— 核心引擎装完即可处理命盘类请求(最多再给卜类引擎 1.5 秒宽限),奇门 / 六壬 / 太乙等卜类请求照旧等全部就绪。平时两者几乎同时完成,只有在首次加载检查拖慢卜类引擎时才体现差别。

## 更新链

- **增量更新更可靠地只下载改动部分**:未改变的大部件(Python 运行时、JDK、星历、天象库、Java 依赖)跨版本字节恒等的保障改为由构建自动完成(以上一版已发布的部件为基准校验),不再依赖人工准备。
- 更新过程中写入部件清单前先清除旧条目;解包始终先删除旧文件再写新文件,不就地覆盖。
- 天象库以只读方式打开,安装目录里不再产生临时文件。

## 其他修复

- 六壬 / 三式合一「昼夜阳阴归属」选项的标签不再在贵人体系不是六壬法时追加括号说明(标签栏太窄时会压到旁边的控件上;说明仍在悬停提示里)。
- **温启恢复到上次停留的页签**:出盘后切换页签也记入温启快照,重开软件回到上次实际停留的页面,而不是上次出盘的页面。
- 更新后第一次启动的会话里手动刷新页面,不再重复显示「更新已完成,正在恢复启动」与首启等待。
- 本地服务的请求日志排除表不再区分大小写(不同大小写写法的同一路径不再漏过排除);日志记录里的密钥类参数按不区分大小写的规则脱敏。
- 冷路径结果统一为纯数据形状落缓存(冷、热两路返回形状一致),并提供 `-Dparamhash.persistable=false` 回到旧行为(仅网页部署可能用到)。
